# 68000 Recap

A refresher, not a course — this assumes you already know at least one retro
CPU and just need the 68000-specific landmarks before reading Amiga
disassembly in Ghidra.

## Registers

Eight 32-bit data registers **D0–D7**, eight 32-bit address registers
**A0–A7**, a 32-bit **PC**, and an 8-bit **CCR** (Condition Code Register —
the user-visible low byte of the 16-bit Status Register). **A7 is the stack
pointer** — but it's banked by privilege mode: in user mode `A7` is the User
Stack Pointer (USP), in supervisor mode the same register number instead
refers to the Interrupt/Master Stack Pointer (ISP/MSP). Two different
physical registers sharing one name in disassembly, selected by CPU mode, not
by anything visible in the instruction encoding.

CCR bits: **X** (Extend, for chained multi-precision arithmetic), **N**
(Negative), **Z** (Zero), **V** (Overflow), **C** (Carry).

Source: *M68000 Family Programmer's Reference Manual*, §1.1 and §1.1.4.

## Big-endian

The 68000 is big-endian — a 32-bit value stored as bytes `00 01 02 03`
reads as `0x00010203`. Confirmed directly in Ghidra's own processor
declaration (`68000.ldefs`: every 68000-family variant has `endian="big"`).
This is the opposite of x86, and the most common trip-up switching from PC RE
work: don't eyeball byte-swapped values as if they were little-endian.

## Addressing modes, as Ghidra prints them

Base 68000/68010 support a subset of the full 68020+ mode table — the ones
below all appear in real Amiga code (the omitted 68020+-only modes — Base
Displacement, Memory Indirect, PC Memory Indirect — won't):

| Addressing mode | Syntax |
|---|---|
| Register Direct (data / address) | `Dn` / `An` |
| Register Indirect | `(An)` |
| — with Postincrement | `(An)+` |
| — with Predecrement | `–(An)` |
| — with Displacement | `(d16,An)` |
| Address Register Indirect with Index, 8-bit Displacement | `(d8,An,Xn)` |
| Program Counter Indirect with Displacement | `(d16,PC)` |
| Program Counter Indirect with Index | `(d8,PC,Xn)` |
| Absolute Short / Long | `(xxx).W` / `(xxx).L` |
| Immediate | `#<xxx>` |

Confirmed this is exactly what Ghidra's shipped 68000 SLEIGH spec emits
(`68000.sinc`, `movemOp` display strings) — same punctuation, just a
Ghidra-internal register token in place of `An`. Source: M68000PRM Table 2-4;
`Ghidra/Processors/68000/data/languages/68000.sinc`.

`–(An)`/`(An)+` are the push/pop convention: predecrement pushes (stack grows
downward), postincrement pops. Source: M68000PRM §2.6.1.

## Instruction patterns worth recognizing

- **MOVEM** (register-list save/restore) — saves or restores multiple
  registers in one instruction, the usual way a function preserves callee-saved
  registers on entry/exit. **Ghidra renders the register list as individual
  space-separated names** (`D2 D3 D4 A2 A3`), not compressed into a range like
  `D2-D4/A2-A3` the way some other disassemblers show it — don't expect range
  syntax in the Listing. Predecrement-mode MOVEM writes the *updated* address
  back into the address register afterward. Source:
  `Ghidra/Processors/68000/data/languages/68000.sinc`.
- **LINK / UNLK** — standard stack-frame setup/teardown. `LINK An,#d16`:
  push `An`, then `An = SP`, then `SP += d16` (reserve `d16` bytes of locals —
  usually a negative literal, since SP grows down). `UNLK An`: `SP = An`, then
  pop the saved value back into `An`. The exact analogue of `push rbp; mov
  rbp, rsp; sub rsp, N` / `leave` if you're coming from x86. Source: same
  SLEIGH file, `:link.w`/`:link.l`/`:unlk` constructors.
- **TRAP #n** — traps through fixed exception vectors 32–47 (`n` = 0–15).
  Not how AmigaOS itself dispatches library calls (see
  [exec.library/Kickstart](03-exec-library-kickstart.md) for the mechanism it
  actually uses), but worth recognizing on other 68k systems, or in
  runtime/compiler support code. Two related vectors worth knowing when
  disassembly hits a word that isn't a real opcode: **vector 10** (`Line 1010
  Emulator`, opcode top nibble `1010`) and **vector 11** (`Line 1111
  Emulator`, top nibble `1111`) — the general 68k mechanism for trapping
  unimplemented opcodes into OS-provided emulation. Source: M68000PRM Table
  B-1.

One label quirk: Ghidra's default `"68000"` language ID actually loads the
68040 instruction set superset (`68000.ldefs` variant `default` uses
`slafile="68040.sla"`) — harmless for real 68000 binaries (they can't contain
68020+-only opcodes), but don't be thrown if Ghidra's own strings say "68040"
for plain 68000 Amiga code.

**Self-check:** you see `movem.l D2 D3 D4 A2 A3,-(A7)` at a function's entry
and the mirror-image `movem.l (A7)+,D2 D3 D4 A2 A3` right before its `rts` —
what's this pattern, and why `-(A7)`/`(A7)+` specifically? → Callee-saved
register spill/restore around the function body; predecrement pushes onto
the downward-growing stack on entry, postincrement pops it back on exit.
