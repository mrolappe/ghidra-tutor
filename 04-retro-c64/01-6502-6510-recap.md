# 6502/6510 Recap

New CPU family for this course — everything before this module was 68000
(`02-retro-amiga/01-68000-recap.md`, `03-retro-atari-st`). The MOS 6502
family is smaller and simpler in most ways (8-bit registers, no privilege
modes, no supervisor/user split), but the C64's actual CPU — the **6510** —
adds one platform-specific wrinkle that matters immediately for Ghidra
work: see "Ghidra has no 6510 variant" below.

## Registers

| Register | Width | Purpose |
|---|---|---|
| `A` | 8-bit | accumulator — the only register most ALU ops can target |
| `X`, `Y` | 8-bit | index registers, used for indexed addressing and as general-purpose counters |
| `SP` | 8-bit | stack pointer — indexes into a **fixed** page, `$0100`–`$01FF` (see below) |
| `PC` | 16-bit | program counter |
| `P` | 8-bit | status/flags register: `N V - B D I Z C` (bit 7→0) — Negative, oVerflow, unused (always reads 1), Break, Decimal mode, Interrupt-disable, Zero, Carry |

No address registers, no separate data/address register files like the
68000 — `X`/`Y` do double duty as both loop counters and address-indexing
sources. There's also no equivalent of the 68000's user/supervisor mode
split: the 6502 has no privilege levels at all, so (unlike the Atari ST
module's `Super()`/mode-switch signal) there's no CPU-mode-based RE signal
to look for here.

## Addressing modes, as Ghidra actually prints them

Confirmed directly against the SLEIGH construct definitions in
`Ghidra/Processors/6502/data/languages/6502.slaspec` (not assumed from
generic 6502 knowledge):

| Mode | Ghidra syntax | Example |
|---|---|---|
| Immediate | `#$xx` | `LDA #$05` |
| Zero page | `$xx` | `LDA $05` |
| Zero page,X / ,Y | `$xx,X` / `$xx,Y` | `LDA $05,X` |
| Absolute | `$xxxx` | `LDA $0500` |
| Absolute,X / ,Y | `$xxxx,X` / `$xxxx,Y` | `LDA $0500,X` |
| Indexed indirect | `($xx,X)` | `LDA ($05,X)` |
| Indirect indexed | `($xx),Y` | `LDA ($05),Y` |
| Indirect (JMP only) | `($xxxx)` | `JMP ($FFFC)` |
| Accumulator | `A` (as the only operand) | `ASL A` |
| Relative (branches) | resolved target address | `BNE $0842` |

The zero-page forms (`$xx`, one byte) are both smaller and faster than the
absolute forms (`$xxxx`, two bytes) — this is *why* zero page is treated as
precious, fought-over RAM on the C64 (see the memory-map guide), not just a
historical curiosity.

## Stack: fixed page $0100–$01FF

Unlike the 68000, where any register can serve as a stack pointer anywhere
in the address space, the 6502's `SP` is an 8-bit index that **always**
addresses page 1 (`$0100`–`$01FF`) — it can never point anywhere else.
Confirmed directly from Ghidra's own processor spec
(`Ghidra/Processors/6502/data/languages/6502.pspec`), which auto-creates a
`STACK` memory block at exactly `start_address="0x0100" length="0x0100"` on
every 6502 program import. Stack depth is therefore hard-capped at 256
bytes — deep recursion or large local-variable frames are structurally
impossible on stock 6502 code, which is itself a useful RE expectation to
carry in.

## Reset/interrupt vectors

Also read straight from `6502.pspec`'s `<default_symbols>` block, which
Ghidra creates automatically on import:

| Vector | Address | Symbol |
|---|---|---|
| NMI | `$FFFA`–`$FFFB` | `NMI` |
| RESET | `$FFFC`–`$FFFD` | `RES` |
| IRQ/BRK | `$FFFE`–`$FFFF` | `IRQ` |

These three words, right at the top of the 64K address space, are where
execution starts (`RES`) and where the CPU jumps on a hardware interrupt
(`NMI`) or a software/maskable interrupt (`IRQ`, shared with the `BRK`
instruction). On the C64 these live inside the KERNAL ROM and get chained
through further RAM-based "soft vectors" the OS provides — covered in the
KERNAL guide.

## Ghidra has no 6510 variant — and no I/O-port modeling

Checked directly in `Ghidra/Processors/6502/data/languages/6502.ldefs`:
Ghidra ships exactly two 6502-family language IDs, `6502:LE:16:default`
("6502 Microcontroller Family") and `65C02:LE:16:default` ("65C02
Microcontroller Family") — **no separate `6510` entry exists.** Every C64
import in this course uses the plain `6502:LE:16:default` processor.

This matters because the real 6510 (the C64's actual CPU) differs from a
stock 6502 in exactly one way that's relevant to reverse engineering: it
has an on-chip 8-bit I/O port at `$00`/`$01` (data-direction register and
port register), used for bank switching — covered in full in the next
guide. Since Ghidra's 6502 language module knows nothing about this port,
**it treats `$00`/`$01` as ordinary RAM** (they fall inside the
auto-created `ZERO_PAGE` block, `$0000`–`$00FF`, also declared in
`6502.pspec`) — no special register names, no bank-switching model, no
warning that writes there change what other addresses in the map actually
mean. Recognizing `$00`/`$01` traffic as *hardware*, not *data*, is
something you bring yourself; Ghidra's static Listing view will show
whatever ROM/RAM/I-O happens to be mapped in at import time and won't
reflect runtime bank changes at all.

---

**Self-check:** you see `STA $01` followed shortly after by code reading
from `$E000`. Nothing in Ghidra's Listing flags this as unusual — why
should it catch your attention anyway? → `$01` is the 6510's bank-switch
port register (not modeled by Ghidra's plain 6502 processor spec); a write
there can change what `$E000` actually contains (KERNAL ROM vs. RAM vs.
cartridge ROM) at runtime, even though Ghidra's static view keeps showing
one fixed interpretation. See [memory map & bank
switching](02-memory-map-bank-switching.md).
